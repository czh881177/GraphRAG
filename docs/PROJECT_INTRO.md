# 医药 GraphRAG 知识图谱问答系统 · 项目介绍书

> **课程实践项目** · 5 人小组 · 2026/9/7 – 2026/9/20（两周）
> **主题**：基于 Neo4j + DeepSeek 的医药领域图增强检索生成（GraphRAG）问答系统
> **定位**：让计算机像"懂行的药师"一样，能回答跨实体、多跳的医药问题，并给出可追溯的依据

---

## 1. 项目概述

### 1.1 要解决的问题

传统 RAG（向量检索 + 生成）只能回答"单点"问题——它把文本切成块、按相似度召回，但**无法把分散在不同文本里的信息关联起来**。

例如问："哪些药物通过抑制环氧合酶（COX）发挥作用？它们由谁研发？"这类问题需要走 **药物 → 作用机制 → 药物 → 公司** 的多跳链路，向量检索给不出答案。

### 1.2 我们的方案：GraphRAG

| 组件 | 作用 |
|---|---|
| **知识图谱（Neo4j）** | 存储"药品 / 疾病 / 靶点 / 公司"等实体及关系，支撑多跳遍历 |
| **向量检索 + 全文检索** | 从医药语料中召回相关文本块（召回证据） |
| **图遍历扩展** | 从命中的文本块出发，沿实体关系向外扩展 1~2 跳，得到三元组证据 |
| **LLM（DeepSeek）** | 融合文本 + 三元组上下文，生成带依据的答案 |
| **前端可视化（D3.js）** | 展示全图 + **金色高亮"答案所依据的子图"** |

### 1.3 项目亮点

1. **多跳推理可解释**：答案不是黑盒，前端会高亮支撑答案的图谱子图
2. **四档检索可对比**：向量 / 向量+图遍历 / 混合 / 混合+图遍历，便于评估图增强的价值
3. **契约先行、两周闭环**：接口契约与 Schema 先定稿，5 人按模块并行开发
4. **合规安全**：语料用公开科普/说明书文本，仅作技术演示，不构成医疗建议

## 4. 系统架构

```
┌─────────────────────────────────────────────┐
│ 前端 frontend/index.html（D3.js 力导向图）      │
│   全图浏览 · 问答面板 · 实体搜索 · 金色子图高亮     │
└───────────────────┬─────────────────────────┘
                    │ HTTP/JSON（CORS，localhost:5000）
┌───────────────────▼─────────────────────────┐
│ 后端 backend/api.py（Flask，7 个端点）          │
│   /api/graph /entities /entity/<id> /stats    │
│   /api/search /api/graphrag /api/health       │
└───────────────────┬─────────────────────────┘
                    │ neo4j-graphrag 组件
┌───────────────────▼─────────────────────────┐
│ 检索/生成 graphragexpr/（4 档检索器）            │
│   Vector / VectorCypher / Hybrid / HybridCypher│
│   ExternalEmbedder（哈希降级）→ OpenAILLM      │
└───────────────────┬─────────────────────────┘
        ┌───────────┴───────────┐
┌───────▼───────┐        ┌──────▼──────────┐
│ Neo4j 5.x 图谱 │        │ DeepSeek LLM    │
│ Document/Chunk│        │ deepseek-chat   │
│ + 6 类实体     │        │ (OpenAI 兼容)    │
└───────────────┘        └─────────────────┘
```

### 数据流

```
医药语料(data/raw)
   → 清洗分块(data/processed, 500–800字/块)
   → LLM 抽取实体关系（6 类本体）
   → Neo4j 建图 + 向量/全文索引
   → 用户提问 → 检索命中 Chunk → 图遍历1~2跳 → LLM 生成答案 → 前端高亮子图
```

## 6. 数据方案

### 6.1 数据来源（公开、无需版权授权）

- 常见 OTC/处方药说明书文本
- 公开健康科普文章（疾病/用药）
- 公开医学知识条目

> 规模目标：**20–40 篇**原始语料，每块 500–800 字、重叠 50–100 字。

### 6.2 本体类型（6 类 + 可选概念）

| 类型 | 含义 | 示例 | 前端色板 |
|---|---|---|---|
| 药物 | 药品/活性成分 | 阿司匹林、布洛芬 | #f72585 |
| 疾病 | 疾病/适应症 | 偏头痛、类风湿关节炎 | #7209b7 |
| 症状 | 症状表现 | 头痛、发热 | #f77f00 |
| 公司 | 药企/研发机构 | 拜耳公司 | #06ffa5 |
| 作用机制 | 靶点/机制 | 环氧合酶、前列腺素合成 | #3a0ca3 |
| 副作用 | 不良反应 | 胃肠道出血、恶心 | #f77f00 |

### 6.3 关系类型

| 关系 | 方向 | 示例 |
|---|---|---|
| 研发 | 公司 → 药物 | 拜耳公司 -研发-> 阿司匹林 |
| 作用于 | 药物 → 作用机制 | 阿司匹林 -作用于-> 环氧合酶 |
| 治疗 | 药物 → 疾病 | 阿司匹林 -治疗-> 头痛 |
| 缓解 | 药物 → 症状 | 布洛芬 -缓解-> 发热 |
| 副作用 | 药物 → 副作用 | 布洛芬 -副作用-> 胃肠道不适 |
| 属于 | 药物 → 药物 | 布洛芬缓释胶囊 -属于-> 布洛芬 |

### 6.4 规模目标（B 负责达成）

实体 ≥ 300、关系 ≥ 500；单块抽取质检合格率 ≥ 80%；孤立节点占比 ≤ 5%。

## 7. 图数据库 Schema（Neo4j）

### 7.1 节点

- `Document`（id, name, text）—— 一篇原始文档
- `Chunk`（text, embedding, index）—— 文本分块，携带 1536 维向量
- 6 类实体节点：`药物` / `疾病` / `症状` / `公司` / `作用机制` / `副作用`（name 为唯一键）

### 7.2 关系

- `PART_OF`：Chunk → Document
- `FROM_CHUNK`：实体 → Chunk（图遍历检索的关键入口）
- 业务关系：`研发` / `作用于` / `治疗` / `缓解` / `副作用` / `属于`

### 7.3 索引（init_schema.py 幂等创建）

- 唯一约束：`Document.id`、`Chunk.index`
- 向量索引 `text_embeddings`：1536 维 cosine
- 全文索引 `text_fulltext`：Chunk.text
- 实体 `name` 索引 × 6

## 8. 后端 API（7 端点）

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | GET | `/api/health` | 健康检查（Neo4j 连通） |
| 2 | GET | `/api/graph` | 完整知识图谱（实体+关系） |
| 3 | GET | `/api/entities?type=` | 按类型/全部实体列表 |
| 4 | GET | `/api/entity/<id>` | 单实体详情与连接 |
| 5 | GET | `/api/stats` | 图谱统计 |
| 6 | GET | `/api/search?q=` | 实体模糊搜索（≤20 条） |
| 7 | POST | `/api/graphrag` | **GraphRAG 问答**（核心） |

### 检索方式（method 枚举）

| method | 召回 | 图遍历 | 说明 |
|---|---|---|---|
| `vector` | 向量 | 否 | 仅返回相关文本块 |
| `vector_cypher`（默认） | 向量 | 是 | 向量召回 + 1~2 跳图扩展 |
| `hybrid` | 向量+全文 | 否 | 需全文索引 |
| `hybrid_cypher` | 向量+全文 | 是 | 混合召回 + 图扩展 |

## 9. 前端功能

1. **知识图谱浏览**：力导向图按类型着色，可缩放拖拽
2. **问答面板**：选择检索方式提问，显示答案
3. **实体搜索**：命中实体在图中高亮
4. **金色子图高亮**：`vector_cypher` / `hybrid_cypher` 回答后，高亮支撑答案的子图
