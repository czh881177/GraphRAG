## 一、项目概述

### 1.1 项目背景

医药领域知识具有高度的关联性：药物作用于靶点、靶点参与生理过程、过程异常导致疾病、疾病表现为症状、药物产生副作用。这些实体与关系天然构成一张复杂的知识网络。

传统的 RAG（检索增强生成）仅基于文本片段的向量相似度召回证据，难以组织跨文档的多跳关联，答案依据难以定位。本项目引入知识图谱，将医药实体与关系结构化存储于 Neo4j，通过图遍历扩展检索上下文，实现可溯源的医药问答。

### 1.2 项目目标

- 构建医药领域知识图谱（药物、疾病、症状、作用机制、副作用、公司、概念 7 类实体）
- 实现四类检索器（向量、图遍历、混合、混合+Cypher）并对比效果
- 接入智谱 embedding-3 语义向量化（1536 维），修复哈希降级导致的语义召回失效问题
- 开发交互式图谱前端（问答、可视化、实体搜索高亮、答案溯源）
- 完成自动化测试与 40 条评估（4 检索器 × 10 问题）

### 1.3 技术栈

| 层次 | 技术 |
|------|------|
| 图数据库 | Neo4j 5.x（Community，Docker 部署） |
| LLM | DeepSeek（deepseek-chat，OpenAI 兼容接口） |
| Embedding | 智谱 embedding-3（1536 维，OpenAI 兼容接口） |
| 后端 | Flask（端口 5000）+ flask-cors |
| 图谱检索 | neo4j-graphrag（VectorRetriever / HybridRetriever / VectorCypherRetriever / HybridCypherRetriever） |
| 前端 | 原生 HTML + CSS + JavaScript（ECharts 力导向图） |
| 测试 | pytest（33 项自动化测试） |
| 版本管理 | Git + GitHub（多分支协作） |

## 二、系统架构

### 2.1 整体架构

系统分为**离线建图管线**与**在线问答流程**两部分，共用同一图谱。

```
┌─────────────────────────────────────────────────────────┐
│                    离线 · 图谱构建管线                      │
│                                                           │
│  医药语料 32 篇 txt                                       │
│      ↓                                                    │
│  实体关系抽取（LLM 结构化）                                │
│      ↓                                                    │
│  语义向量化（智谱 embedding-3，1536 维）                  │
│      ↓                                                    │
│  Neo4j 入库（节点与关系 + 向量索引 + 全文索引）            │
│      ↓                                                    │
│  图谱质检（连通性、去重、坏边检查）                        │
└─────────────────────────────────────────────────────────┘
                        ↓ 共用图谱
┌─────────────────────────────────────────────────────────┐
│                    在线 · 问答流程                          │
│                                                           │
│  用户问题（自然语言）                                       │
│      ↓                                                    │
│  混合检索（向量 + 关键词）→ 图遍历扩展（一跳邻居与路径）   │
│      ↓                                                    │
│  LLM 生成（DeepSeek，temperature=0）                      │
│      ↓                                                    │
│  答案 + 子图（可溯源展示）                                  │
└─────────────────────────────────────────────────────────┘
```

### 2.2 后端 API 端点

| 方法 | 端点 | 功能 |
|------|------|------|
| GET | `/api/health` | 后端与 Neo4j 连通性检查 |
| GET | `/api/graph` | 获取全量知识图谱（节点+边） |
| GET | `/api/entities` | 实体列表（可按类型过滤） |
| GET | `/api/entity/<id>` | 单个实体详情（含关联关系） |
| GET | `/api/stats` | 图谱统计（实体/关系数量及分布） |
| GET | `/api/search?q=` | 实体名称模糊搜索 |
| POST | `/api/graphrag` | GraphRAG 问答（支持 vector / vector_cypher / hybrid / hybrid_cypher 四种方法） |

## 三、图谱数据

### 3.1 数据规模

| 指标 | 数值 |
|------|------|
| 原始语料 | 32 篇医药领域专业文本（.txt） |
| 实体节点 | 568 个 |
| 关系边 | 858 条 |
| 实体类型 | 7 类 |

### 3.2 实体类型分布

| 实体类型 | 数量 |
|----------|------|
| 概念 | 128 |
| 疾病 | 87 |
| 副作用 | 88 |
| 症状 | 84 |
| 作用机制 | 76 |
| 药物 | 84 |
| 公司 | 21 |

### 3.3 建图流程

1. **语料清洗**：32 篇医药文本统一 UTF-8 编码，去除无关格式
2. **实体关系抽取**：通过 LLM 结构化抽取实体与关系三元组
3. **语义向量化**：使用智谱 embedding-3 为每个 Chunk 生成 1536 维向量
4. **Neo4j 入库**：创建实体节点、关系边，建立向量索引（`text_embeddings`）与全文索引（`text_fulltext`）
5. **图谱质检**：实体去重合并、同义写法归一、关系类型归一化、坏边检查（0 条无效边）

### 3.4 Schema 设计

核心标签：`药物`、`疾病`、`症状`、`公司`、`作用机制`、`副作用`、`概念`、`Chunk`、`Document`

核心关系类型：`作用于`、`抑制`、`导致`、`缓解`、`研发`、`属于`、`FROM_CHUNK` 等

`Chunk` 节点通过 `FROM_CHUNK` 关系关联到实体，支持向量检索结果向图结构的回溯。

## 四、检索与生成

### 4.1 四类检索器

| 检索器 | 类名 | 原理 |
|--------|------|------|
| 向量检索 | VectorRetriever | 问题向量化，按语义相似度召回 Chunk |
| 图遍历检索 | VectorCypherRetriever | 向量召回 Chunk 后，通过 Cypher 沿 `FROM_CHUNK` 扩展实体及一跳邻居 |
| 混合检索 | HybridRetriever | 向量检索 + 全文关键词检索结果融合排序 |
| 混合+Cypher | HybridCypherRetriever | 混合检索 + 图遍历扩展上下文（推荐） |

问答默认采用「混合 + 图遍历」组合，兼顾语义召回与图结构上下文。

### 4.2 Embedding 修复历程

**问题**：外部 Embedding 服务调用失败后，系统降级为本地哈希向量。哈希向量不含语义信息，向量检索近似随机，相关实体无法被召回，导致 3 个检索器返回「无法回答」。

**修复**：接入智谱 embedding-3（1536 维），重建全库向量后语义召回恢复。修复后 10 题标准测试集四种检索器全部答对。

### 4.3 LLM 生成

使用 DeepSeek（deepseek-chat），temperature=0 保证答案稳定性。Prompt 模板明确要求：
- 仅根据提供的上下文回答
- 优先使用知识图谱关系信息
- 上下文不足时明确说明，不编造医学事实

## 五、前端界面

### 5.1 功能特性

- **问答交互**：输入自然语言问题，返回系统答案与相关子图
- **图谱可视化**：ECharts 力导向图展示实体与关系，支持拖拽缩放
- **实体搜索**：输入实体名，图中对应节点高亮定位（紫色光环 + 放大），一跳邻居轻度高亮，无关节点变暗，自动聚焦首个命中
- **答案溯源**：答案展示实体路径与依据子图，支持逐条核验
- **类型过滤**：按实体类型筛选显示

### 5.2 设计风格

白色为主的简洁高级界面：浅渐变背景、玻璃拟态头部、卡片式侧边栏、点状图画布、精致微交互。实体节点按类型着色，关系边灰色细线。

### 6.1 自动化测试

### 6.2 40 条评估

评估脚本 `evaluate_all.py` 自动运行 **4 检索器 × 10 问题 = 40 条**问答，结果保存于 `docs/EVALUATION_RESULTS.txt`。

10 个测试问题覆盖单跳、多跳与风险类：
1. 阿司匹林的作用机制是什么？
2. 哪些药物通过抑制环氧合酶发挥作用？
3. 布洛芬有哪些副作用？
4. 拜耳公司研发了哪些药物？
5. 服用阿司匹林会引发什么症状？
6. 拜耳公司研发的药物有哪些副作用？
7. 环氧合酶与哪些药物有关？
8. 对乙酰氨基酚的作用机制与布洛芬有什么不同？
9. 哪些药物可以治疗头痛？
10. 长期服用布洛芬有什么风险？

四个检索器均能正常输出答案，无「无法回答」或「未解析」情况。

## 八、使用说明

### 8.1 环境要求

- Python 3.12（勿用 3.14）
- Docker Desktop（运行 Neo4j）
- Git

### 8.2 快速启动

```powershell
# 1. 克隆仓库
git clone https://github.com/czh881177/GraphRAG.git
cd GraphRAG

# 2. 创建虚拟环境并安装依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. 配置环境变量
copy .env.example .env
# 编辑 .env，填入 LLM_TOKEN（DeepSeek）和 EMBED_TOKEN（智谱）

# 4. 启动 Neo4j
.\start_neo4j.ps1

# 5. 初始化 Schema 与索引
.\.venv\Scripts\python.exe scripts\init_schema.py

# 6. 构建知识图谱
.\build_kg_dyn.ps1

# 7. 启动后端 API
.\start_backend.ps1
# 访问 http://localhost:5000

# 8. 打开前端
# 浏览器打开 index.html（需后端运行中）
```

### 8.3 运行测试

```powershell
.\run_tests.ps1
# 或
.\.venv\Scripts\python.exe -m pytest tests/ -v
```

### 8.4 运行评估

```powershell
.\.venv\Scripts\python.exe evaluate_all.py
```
